# 体験記型の記事の書き方

## いつ読むか

体験記型の記事（やってみた記録・受験記・移行記など、書き手が実際に通った経路そのものが中身になる記事）を書くときに読む。概念解説型は `concept.md`、ハマりどころ型は `troubleshooting.md`、手順型は `howto.md` を読む。

読むタイミングは記事タイプを体験記型と判定した直後、構成を決める前。この型だけは他の 3 タイプと目的が違う。他の 3 タイプが読者の理解モデルや再現手順を作るのに対し、体験記が渡すのは「自分もやるべきか」を判断するための一次情報である。

## 必要な入力

共通の核（`planning.md`）に加えて、次を確定する。

- **着手時点の自分の状態**: 経験年数、既に知っていたこと、知らなかったこと。読者が自分と比較する基準になる
- **動機**: なぜやったのか。業務上の必要、資格の期限、興味のどれか
- **実施したこと**: いつ、何を、どの順で。判断が分かれた場面ではその時点で何を知っていたか
- **結果と学び**: どうなったか。効いたことと効かなかったこと
- **数字**: 所要時間、費用、試行回数、スコア

数字が手元にない場合は、概算であることを明記して書く。数字のない体験記は、読者が自分に当てはめる目安を持てない。

## 記事の骨格

| 位置 | 置くもの |
| --- | --- |
| 冒頭 | 着手時点の自分の状態と動機 |
| 駆動軸 | 時系列 |
| 末尾 | やってよかったこと・次にやる人へ |

冒頭に置くのは読者の現在地ではなく**書き手の現在地**である。読者が知りたいのは「自分もやるべきか」であり、その判断材料は書き手がどこから始めたかだから。「業務で 3 年触っているが資格は未取得」と「完全に未経験」とでは、同じ所要時間の記述がまったく違う意味を持つ。

駆動軸は時系列にする。概念の依存関係や手順の段階で並べ替えると、書き手が何をどの順で知ったかという情報が消える。読者が追体験できるのは、書き手が実際に通った順序だけである。

## 固有の書き方

### 体験記型で効くこと

体験記の価値は一貫した理解モデルではなく、追体験できる具体性と一次情報としての正直さにある。理解モデルを組み立てようとすると、体験が一般論に薄まる。

- **時系列と判断を記録する**: 何をいつやったかだけでなく、その時点で何を知らず、なぜそう判断したかを書く。判断理由のない時系列は作業ログにしかならない
- **失敗と遠回りを削らない**: うまくいった経路だけを残すと、読者は同じ道を通れない。詰まった箇所こそ読者が知りたい部分
- **数字を出す**: 所要時間、費用、試行回数、スコア。数字がないと、読者は自分に当てはめる目安を持てない
- **再現条件を示す**: 環境・バージョン・前提。同じ結果が誰にでも出るとは限らないことを断る
- **一般論に逃げない**: 「継続が大事」で締めない。自分に何が効いて何が効かなかったかを書く

### 「説明の組み立て」の適用範囲

`writing.md` の「説明の組み立て」のうち、体験記型に当てるのは次の項目だけである。

- 専門用語は役割を説明した後に導入する
- 抽象と具体を短い間隔で往復する
- 図には一つの役割だけを持たせる
- 単純化した箇所を明示する
- トレードオフを示す

残る 3 項目（問題起点で説明する / 既知と未知を分離する / 詳細度を階層化する）は当てない。これらは読者の理解モデルを組み立てるための道具であり、体験記に当てると、書き手が実際に通った順序が「読者にとって分かりやすい順序」へ組み替えられてしまう。組み替えた時点で追体験できる記録ではなくなる。

## セルフレビュー項目

`review.md` の共通点検に加えて、次を確認する。

- [ ] 時系列と、その時点での判断理由が書かれているか
- [ ] 失敗・遠回りを削っていないか
- [ ] 数字（所要時間・費用・試行回数）が出ているか
- [ ] 再現条件（環境・バージョン・着手前に何をどこまで知っていたか）が示されているか
- [ ] 冒頭で示した動機や目的が、末尾で回収されているか
- [ ] 「継続が大事」のような一般論で締めていないか
