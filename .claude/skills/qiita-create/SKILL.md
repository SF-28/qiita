# Qiita 記事作成

技術記事を新規作成し、限定共有（`private: true`）の状態で完成させる。

記事の品質は書き始める前の設計で決まる。テーマを受け取ってもすぐには書き始めない。

## Workflow

1. テーマを聞く
2. 記事タイプを推定し、対応する参照ファイルを読む
3. 対話で記事の核を固める
4. 構成（H2 レベル）を設計する
5. 記事ファイルを作成する
6. 執筆する
7. セルフレビューし、本文を修正する
8. 完了報告を出力する

一度に複数ステップを進めない。各ステップの結果をユーザーに見せてから次へ進む。ただし「一気に書いて」「任せる」と求められている場合は、テーマとタイプの確認だけ取って最後まで進む。

## テーマ

「何について書きますか」から始める。手元に素材（メモ・作業ログ・コード・エラーの記録・過去の会話）があれば出してもらう。

すでに会話の中でテーマや素材が出ている場合は聞き直さない。

## 記事タイプ

テーマと素材からタイプを推定し、ユーザーに確認する。判定をユーザーに丸投げしない。

| タイプ | 判定基準 | 参照ファイル |
| --- | --- | --- |
| 概念解説型 | 記事の中心が概念の理解にある（例: Ragas の評価指標、graph engineering） | `references/concept.md` |
| ハマりどころ型 | 特定の失敗と、その原因・回避策を残す（例: ECS Fargate のつまずき、AFT の OU 未登録エラー） | `references/troubleshooting.md` |
| 手順型 | 導入・移行・構築を読者に再現させる（例: mkdocs でのサイト作成、pnpm への移行） | `references/howto.md` |
| 体験記型 | やってみた記録・受験記（例: SAP-C02 合格体験記、Amazon Q CLI でテトリス） | `references/experience.md` |

判定に迷ったら、記事の中心が「概念の理解」なら概念解説型、「手を動かした結果」ならそれ以外とする。

判定したタイプの参照ファイルを**必ず読んでから**核の対話へ進む。タイプによって聞くべきことが変わる。

## 記事の核

`references/planning.md` の対話手順に従って、ユーザーと一緒に固める。

確定させるのは 主張 / 読者 / 差分 / スコープ / 根拠 と、タイプ固有の入力。ただし**この項目名でユーザーに問いを投げない**。項目はこちらの確認用チェックリストであって、質問票ではない。

- 素材と会話から埋められるものは、こちらで仮案を作って確認だけ取る
- 埋まらないものを、一度に 1〜2 個ずつ聞く
- 「任せる」「一気に書いて」と言われたら、仮案を確定として先へ進む

## 構成

`references/planning.md` の「構成設計」と、判定したタイプの参照ファイルの「記事の骨格」に従って H2 構成を作る。

- 対話形式で進めている場合は、構成を提示して確認する
- 一括作成・完成稿を求められている場合は、合理的な仮定を置いて最後まで進める
- 構成がユーザーから指定されている場合は、問題がない限り尊重する

## ファイル作成

```bash
mise run new <basename>
```

- `<basename>` は記事タイトルの要約を日本語含む kebab-case で指定する（例: `terraformでaws-control-tower-account-factoryを使ったら-ou-is-not`）
- 生成されるファイルは `public/YYYY-MM-DD_<basename>.md`（日付は自動付与）。`private: true` を維持する
- `organization_url_name` は変更しない

## 執筆

- `/stop-ai-slop-jp` を適用する
- `references/writing.md` の規則に従う
- 判定したタイプの参照ファイルの「固有の書き方」に従う

## レビューと完了

`references/review.md` と、判定したタイプの参照ファイルの「セルフレビュー項目」で点検する。問題を列挙するだけで終わらせず、本文を修正する。

完了条件:

- 記事ファイルが `public/` に作成されている
- `private: true` である
- 核で決めた主張が本文で明示されている
- セルフレビューで検出した問題が本文に反映されている

完了後、以下を出力する:

```
## 記事作成完了

- **ファイル**: public/<basename>.md
- **タイトル**: <title>
- **ステータス**: 限定共有（private: true）

### 次のステップ
1. 内容を確認し、push してください
2. CI が記事を Qiita に反映します（限定共有として）
3. 承認に出す場合は `/qiita-approve` で申請情報を出力できます
```
